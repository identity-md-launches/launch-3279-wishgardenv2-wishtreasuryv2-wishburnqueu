# Adaptation of the pinned Wish Garden

This is a substantive contracts-only replacement, not a redeployment of the old free-claim/sink design. Existing build configuration, compiler settings and dependencies were not changed. No new token, pool, website, IPFS host, proxy, pause, blacklist, arbitrary-call mechanism or holder financial rights were added. No legacy transaction, key access, factory call, source publication or production broadcast was performed here. Service deployment/publication and the owner's separate Base deployment remain explicit handoff stages.

## Imported findings: reproduction and disposition

1. **Duplicate free claims (`8cb9a97d…`) — reproduced and fixed.** `LegacyRegistryTest.test_reproducedOriginalSecondLedgerFindingThenReplacementRejects` claims NFT 7 in two old-source instances; both give a candle. The replacement rejects both removed selectors; the original ledger remains lifetime-bound after NFT transfer.
2. **Locked allocation instead of real burn (`744109da…`) — reproduced and fixed in replacement.** The historical tests and `test_paidLegacyCandlesAndFundsStayVisibleAsLocked` show old paid funds in the sink and zero supply burned. New bridge tests prove pending/in-transit separation and confirmation only after an exact Base burn/ack. Old sink funds remain unrecoverably locked; no claim to fix a deployed legacy contract is made.
3. **ID/position collision (`8986adb4…`) — reproduced and fixed.** Two legacy instances produce ID 1/position 0. Replacement IDs/positions begin in the high-bit range and canonical keys also include the source contract, so namespaces do not rely solely on a numeric offset.
4. **No text/registry (`01d026b7…`) — reproduced and fixed.** The archived original rejects the new text selector and has no corresponding record storage. New tests cover malformed UTF-8, scalar/byte bounds, atomicity, acknowledgement, recorded author, immutable text and retry without buying.
5. **Recipient permissions outlive ownership (`ec87fe86…`) — reproduced and fixed.** Historical treasury ownership transfer leaves operations claims with the former owner-recipient and rejects the new owner. The replacement regression shows new owner access to operations/founder and old owner rejection.
6. **Stale launch manifest (`65059822…`) — reproduced and addressed.** The original manifest deployed old sink/treasury/garden constructor shapes. It was removed and handoff reconciled for three new Ethereum applications. The separate manifest step must generate the root manifest after review.
7. **Review-coverage/status report (`687ff808…`) — informational, not a reproduced exploit.** Read the named source and protected checks. Current pinned read-only observations again show legacy totalCandles/freeCandles/totalPayments zero, unconfirmed collection and unbound treasury at the recorded Ethereum block. Ethereum/NFT runtime hashes match historical evidence; source/runtime compatibility is exercised offline. There is no new evidence justifying an unrelated redesign of legacy behavior. The absent imported `floor/OwnerChecks.sol` and service environment prevent running the supplied protected wrapper directly here; equivalent local constructor/owner/size/opcode rehearsals run in the delivered suite. Final protected checks/independent review remain service responsibilities.

No actionable imported finding was rejected as unreproduced. The seventh entry is coverage/status context and the sixth is manifest metadata, not a code vulnerability. The local adversarial review is documented in `docs/validation.md`; it is not represented as a new independent contributor's approval.

## Additional author review finding

A synthetic maximum-namespace state reproduced an exclusive pagination cursor overflow: allowing the largest uint256 candle ID would make `lastId + 1` overflow. The replacement now reserves that last value as the exclusive cursor and rejects purchases before exhausting it. `test_namespaceBoundaryReservesExclusivePageCursor` covers the boundary. This changes only an astronomically unreachable edge, not practical supply or batch behavior.

## Deliberate operational choices and limitations

- Constants: 1 IMD; 30/50/10/10; seven styles; batch 50; page 100; 280 scalars/1120 bytes; high-bit paid namespace; actual OFT conversion unit 10^12; application payload version 1; fixed callback index 0. Gas option bounds are 100,000–5,000,000, with 300,000 used as an initial **simulation** value. They are documented, not economic changes.
- Burn source dispatch is permissionless but destination-restricted; anyone can fund its native gas. Base acknowledgement is a separate call so a temporary return-fee failure never forces a second burn. Failed source sends revert completely; delayed destination/return work remains in transit. No failure path silently reports success or withdraws the burn allocation.
- Owner verification of the actual receiver source and both routes is essential before activation. An evidence hash is a commitment, not verification of remote code/DVNs/credit. New applications use LayerZero default routes and expose no delegate/message-library override; unsuitable defaults block activation. External bridge governance remains a disclosed trust assumption.
- Confirmed Ethereum deployment/publication and Base receiver address are intentionally absent until the respective service/owner acts. The brief explicitly provides disabled deployment and one-time setup for these unknowns, so no requester-only input blocks this bounded source revision and no stand-in is introduced.
